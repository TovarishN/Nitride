# Shared-parser per-rule cost, November 12

Cold CSharp4 parses through the generated parser, on `claude/parser-kept-path-speed`
against `main` (465f810). Measured on one Apple M4 Pro (macOS, rustc 1.99.1), with
portable release builds of the [compiler-audit harness](../../../scripts/compiler-audit/README.md):
full LTO, one codegen unit, no PGO and no SIMD features.

## Changes

- **Boxed child-buffer pool.** Each rule attempt takes a child buffer from a pool
  and returns it. The buffer is about 112 bytes and was moved by value three times
  per attempt; boxed, only a pointer moves.
- **Cold-parse fast paths.** Without a previous child list, as on a cold parse,
  a child buffer keeps its children directly rather than reuse part descriptors,
  and the prior-node search returns at once instead of searching an empty scope.
- **First-token rejection at rule entry.** A syntax rule whose first-token set
  excludes the next character fails at entry, before allocating a buffer or running
  its body. It records the failure position its first step would and observes the
  character it decided on. Precedence (Pratt) rules are excluded.

## Results

Medians of nine rounds in alternating build order, one parse per process.
Times exclude process start, source reading, tree export and fingerprinting.

| Input | Mode | `main` ms | Branch ms | Change |
|---|---|---:|---:|---:|
| 256 KiB valid | strict | 52.54 | 45.52 | −13.4% |
| 4 MiB valid | strict | 809.00 | 705.40 | −12.8% |
| 16 MiB valid | strict | 3,321.28 | 2,904.78 | −12.5% |
| 256 KiB one error | recovering | 64.78 | 58.37 | −9.9% |
| 4 MiB one error | recovering | 986.67 | 886.87 | −10.1% |
| 4 MiB junk | recovering | 988.86 | 889.21 | −10.1% |
| 256 KiB dense errors | recovering | 363.19 | 349.30 | −3.8% |

## Parity

Every generated input (64 KiB to 4 MiB; valid, one error, junk, dense errors,
truncated) and the 19 Mono corpus files, in strict and recovering mode: 69 runs.
Tree fingerprints (nodes, spans, labeled edges, diagnostics and recovery records)
and diagnostic counts are identical in every run.

Logical work changes where rules are rejected at entry. Strict valid generated
inputs charge 2.4% less; Mono corpus files charge 2.2–11.8% less. Damaged
generated inputs charge the same. Generated and interpreted parsing share the
changed path, and the workspace test that requires their logical work to match
still passes. Work bounds the parse budget, so lower counts never stop a parse earlier.

## Limits

- One host and one synthetic corpus shape; cold parses only. Edits, PGO builds,
  peak memory and the .NET comparisons were not remeasured.
- Fingerprints establish equivalence between the two builds on these inputs,
  not independent C# correctness.

## Reproduce

```sh
cargo build --release --manifest-path scripts/compiler-audit/Cargo.toml --target-dir target/a
# check out the other revision, then
cargo build --release --manifest-path scripts/compiler-audit/Cargo.toml --target-dir target/b
python3 -I scripts/compare_parser_builds.py target/a/release/nitride-compiler-audit \
    target/b/release/nitride-compiler-audit --rounds 9 --work-may-differ --report target/reports/kept-path.json
```
