# Built-in values, text literals and source checks

Stage ten admits a DateCalc-shaped `Dates` profile. It covers DateCalc's
built-in values, checked date literals and date/duration overloads, but not its
rewrites, calls or C# helpers. The pure `languages/dates/Dates.ngr` and
`catalog.json` build natively. Cargo uses no .NET component.

## Admitted contract

- **Built-in values.** `builtin value { pi today }` declarations are typed by
  `catalog.values[kind][name]`. Binding tries every visible local kind first,
  then built-in values in authored kind order, as Nitrogen Project.Lookup does.
  A local `pi` hides the built-in only after its declaration. The initializer
  `let today = today + 2 days;` reads the built-in. HIR records
  `{kind:"reference", builtin:"today"}` and never fabricates a declaration.
- **Host values.** `HostValue::new(kind, name, type, provider)` supplies values.
  `preflight_with_values` rejects missing, duplicate and mistyped values.
  `execute_with_values` reads each value at most once per execution, after
  complete preflight, matching DateCalc's single evaluation context per run.
  Reads are not operation trace entries; actual Nitrogen does not trace them
  either.
- **Text arguments.** `lowers Op(text Field)` is now admitted syntax. It
  normalizes to positional `text_args` indices, which the live exporter emits
  too. Codegen requires each marked position to be a `Core.Text` input, and
  every `Core.Text` input to be marked. HIR holds a `Text` node whose spelling
  lives in `Program::text`. Text operations need a `HostBinding::text` handler
  and a single input. No operation may return text, overload groups cannot take
  it, and literals cannot be typed as text. Preflight rejects text that is a
  statement result, is shared between operations, or feeds a numeric input.
- **Source checks.** `catalog.checks[rule]` entries name a code, a rule field, a
  predicate and a message. The only predicate is `iso-date`: an exact
  `yyyy-MM-dd` proleptic Gregorian date, year 1 to 9999. It is engine code, not
  translated C#. A failed check is a `check` diagnostic carrying its code.
  Checks are collected with type diagnostics and selected by source start, with
  inner (postorder) facts first. Live probes show the same order in Nitrogen:
  `2026-02-30 + 1;` reports DATE0001 before the enclosing overload error, while
  `1 + 2026-02-30;` reports the overload error, which starts earlier.

Older profiles keep their generated rules apart from two new empty fields.
`Language.checks` and `Action::Operation.texts` are empty, and
`Action::Reference.values` is empty unless built-in values are declared.
Template profiles reject values, checks and text operations.

## Grammar bootstrap

`Grammar.ngr` adds `Argument = TextArgument / Word` with a lexical
`TextKeyword = "text" !NameTail`. A syntax-level `!NameTail` skips trivia first
and would have rejected `text V`. The token form also keeps a field named `text`
working, as in `Op(text)` and `Op(text text)`. The seed was regenerated by the
running frontend, and `bootstrap -- --check` confirms the fixed point. The only
other seed change is the emitted `checks:&[]` field.

## Validation

- RED first: the preparation test failed on `text V` before the grammar
  change, and a codegen variant with an unknown empty value namespace was
  admitted until validation was added.
- 111 Rust tests, formatting and strict clippy pass. The new tests cover frozen
  parity, read-once values, missing/duplicate/mistyped values with zero reads,
  codes on checks, text handler admission, handcrafted text HIR misuse, 23
  malformed catalog/text/check variants and calendar edge cases.
- 31 new frozen Dates observations from actual Nitrogen match native output:
  syntax, bindings, HIR (including `text` and built-in references), check
  codes, values and traces. Expected values were computed independently with
  Python `date.toordinal()` before freezing. Another 64 generated programs match
  live Nitrogen.
- `scripts/prepare_parity.py` compares 82 prepared profiles, including Dates and
  four text-label variants, against the live exporter; 16 invalid grammars are
  rejected by both.
- All earlier frozen and generated live comparisons still pass: 220 frozen and
  448 generated observations in total.
- A self-review found two issues, both fixed and rerun. A check over an absent
  field now fails as a check instead of aborting, and the oracle reads check
  codes from the catalog. No independent reviewer was run.
- Nitrogen's workspace checker, given an explicit input manifest, passes the
  Dates sample. A temporary `2026-02-30;` reports
  `DATE0001: not a calendar date` at 1:1 and is then removed. Live VS Code and
  Rider interaction is unverified.

## Footprint

The macOS arm64 release CLI is 835,216 bytes, +16,816 from stage nine. The
profiler is 536,400 bytes. The core still has no third-party dependencies.
`stage10-{namespace,inference,calls,functions}-memory.json` repeat the
10/100/1000-pair workloads. Every allocation count, retained byte and peak
matches stage nine. Only the pre-phase process baseline moved, by 16 to 48
bytes. `stage10-dates-memory.json` adds the new workload: at 1000 pairs, HIR
allocates 8,118 times and retains 796,672 bytes. Elapsed times vary and are
not a throughput claim.

A clean source-only copy (no tools/, language.json, C# helpers or
.Reference.ngr) builds offline with PATH restricted to system tools and no
.NET on it. In that copy the bootstrap check passes, Dates prepares, and the
sample returns `[739907, 81, 6.283185307179586, 19]`. An invalid
`--today 2026-02-30` is refused. .NET is still installed elsewhere on the host.

## Limits

No built-in value calls, value-returning text, general text values, scoped
built-ins, DateCalc rewrites/quasiquotation, `weekday`/Math functions or C#
translation. `today` is a host input with no time-zone policy; the CLI uses the
UTC date unless `--today` is given. Durations are whole-day `f64` counts in this
fixture host, and the reference host uses the same day-number arithmetic.
