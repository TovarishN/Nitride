Continue the Rust-only, small-native-engine project inline. The user's Continue
following the bootstrap discussion authorizes this next bounded milestone.

## Contract

Describe the currently admitted .ngr syntax in `languages/grammar/Grammar.ngr`.
Use nitride-core's generated parser for recognition, then decode its syntax tree
into the existing preparation model. Rust still performs model construction,
literal decoding, module resolution and admission checks. Full Nitrogen.ngr,
C# semantics, recovery and editor services remain outside this milestone.

Check in one generated Rust seed table, compiled directly by nitride-prepare.
It breaks the build cycle: no build script calls prepare to build itself.
Regeneration prepares Grammar.ngr with the running frontend, emits a new table,
and must reproduce the checked-in seed byte for byte. Repeating with the rebuilt
frontend proves a fixed point. Keep an independent .NET syntax/export comparison.
No .NET or pre-exported JSON enters ordinary Cargo builds.

Preserve supported profiles and frozen observations. Parser errors retain UTF-8
file/line/column locations; generic generated syntax messages may replace the
handwritten parser's wording. Literal/semantic errors remain specific. Keep
bounded parse/decode work and reject malformed/unsupported constructs.

## Review focus

Opaque blocks must not consume closing module braces or mistake quoted/commented
braces for delimiters. Reserved expression words and touching grammar calls must
not silently gain admission. Unterminated comments cannot be accepted as EOF.
Parser/decode limits must fail without stack overflow. Generated grammar changes
must fail CI when the seed is stale, including source-identity-only changes.

Task 1 complete: initial fixed-point test failed for the absent grammar project;
one-time native seed and source grammar added, normalized output matches actual
Nitrogen. Task 2 complete: 99 workspace tests pass, including twelve bootstrap and
boundary tests. Range punctuation, raw C# strings, lowering keyword fallback,
opaque character scanning and unterminated comments were reproduced RED and
corrected GREEN. Strict-comment handling is opt-in; existing runtime behavior is
required by actual frozen reference cases and remains unchanged.

Ruling: generated parsing uses the preparation-specific 512 parser-frame limit, rather than the
handwritten parser's expression/unary depth counter. This can reject deeply nested
grammars earlier; the bound and generic syntax messages are documented. Existing
admitted profiles and live preparation corpus remain unchanged.

Task 2 follow-up: probing showed 128 parser frames rejected only four nested
groups. A twelve-group test failed RED. Preparation now explicitly allows 512
parser frames; the test passes alongside 300-deep group/opaque/postfix rejection
without stack overflow. Core defaults stay 128. The exact old depth-counter limit
is not reproduced, but normal nesting has a dedicated regression.

Final review: one independent reviewer found two actionable defects. Reserved
labels after an existing sequence element gained admission (P2); twelve nested
groups each with 128 postfix wrappers could overflow a 2 MiB thread stack (P1).
Both reproduced RED. A sequence-tail !Reserved guard retains first-position
label support. A bottom-up postorder preflight bounds total decoded model depth
before JSON construction, separated-list cloning or normalization. Both tests
pass GREEN; the stack regression runs in a subprocess on an explicit 2 MiB thread.
The reviewer compared 92 additional expression forms; no other findings.

Final rulings on declined review scope: exact historical nesting thresholds are
replaced by the documented generated-frame/model-depth bounds; crashes remain
unacceptable and now regress. Opaque C# validity and full Nitrogen coverage stay
outside admission. Live IDE behavior and independently repeated benchmark review
are unverified; actual workspace checks and author measurements are reported
separately. No deferred minor code findings.
