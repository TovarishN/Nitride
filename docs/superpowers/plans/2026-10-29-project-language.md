# Project Language (`.nproj`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `nitride.json` (and, for Nitride, `languages/*/project.json`) with per-folder `.nproj` files and a root `nitride.nproj`, parsed by a Nitride-defined grammar that Nitrogen will mirror.

**Architecture:** Copy the catalog-language pattern. `languages/project/Project.ngr` defines the language. A checked-in seed frontend (`project_seed.rs`, regenerated by the bootstrap example) parses it, and a decoder in `nitride-prepare` (`nproj.rs`) resolves it with spans into a `ProjectLanguage`. `prepare_project`, the CLI, the LSP registry and the VS Code extension consume that. `nitrogen.json` stays as an editor fallback. `project.json` files stay for the C# comparison scripts. Both are removed in phase 3, which is not in this plan.

**Tech Stack:** Rust (nitride-prepare, nitride-codegen, nitride-lsp, nitride-cli), TypeScript (editors/vscode), `.ngr` grammars.

**Spec:** `docs/superpowers/specs/2026-10-29-project-language-design.md`

## Global Constraints

- The syntax, rules, error list and examples are exactly as in the spec ("Syntax", "Rules", "Errors").
- No `mode` keyword: having at least one `catalog` means typed, and having none means syntax.
- Paths are relative to the containing `.nproj`'s directory and written with `/`.
- `nitrogen { }`: `namespace` is required. If `grammar` is present, it *replaces* the outer grammar list for Nitrogen. Nitride only checks that its paths exist.
- Prepared output (`language.json`), grammars, catalogs and codegen are unchanged.
- LSP and VS Code lookup order at a folder root: `nitride.nproj`, then `nitrogen.json`. `nitride.json` is no longer read.
- **Transition (amends the spec):** `nitride prepare` keeps accepting `project.json` as well as `.nproj`, because `scripts/prepare_parity.py`, `test_composition.py` and `csharp4_reference.py` hand the same `project.json` to both implementations. Only `.nproj` gets "catalog implies typed". The JSON path stays as it is. Both go in phase 3.
- `languages/signed` is untouched.
- The bootstrap fixed-point check (`cargo run -p nitride-prepare --example bootstrap -- --check`, run in CI) must pass after every task that touches a grammar.

## Review Focus

1. **A `.nproj` that is half-typed in the editor** (unparseable). The language keeps its previous state, as an unreadable manifest does today, and the error is shown on that file only. Test in Task 5.
2. **`include` of a folder that is missing, or holds zero or two `.nproj` files.** There is an error on the `include` path's span in `nitride.nproj`, and the other includes still load. Tests in Task 2 and Task 5.
3. **Two languages claim the same extension.** There is an error on the later language's `extensions` span, the earlier language keeps the extension, and the later language still loads with its remaining extensions. Test in Task 2.
4. **A folder with both `nitride.nproj` and `nitrogen.json`.** Only `.nproj` is read and `nitrogen.json` is ignored without any diagnostic. Test in Task 5.
5. **A `start` rule that isn't in the grammars** (a typo after a rename). The error goes on the `start` name's span in the `.nproj`, not on line 1 of the first grammar. Tests in Task 4 (prepare) and Task 5 (LSP diagnostic).

The grammar is the contract Nitrogen generates from, so it is fixed here:

```ngr
// Nitride projects: one language per folder, or the workspace that lists them.
syntax module NitrideProject
{
  token IdStart = ['a'..'z' 'A'..'Z' '_'];
  token IdPart = ['a'..'z' 'A'..'Z' '0'..'9' '_'];
  token Identifier = IdStart IdPart*;
  token QualifiedName = Identifier ("." Identifier)*;
  token Extension = "." IdPart+;
  token PathPart = ['a'..'z' 'A'..'Z' '0'..'9' '_' '-' '.']+;
  token Path = PathPart ("/" PathPart)*;

  syntax File = Item:(Workspace / Language);
  syntax Workspace = "workspace" "{" Includes:Include* "}";
  syntax Include = "include" Path:Path ";";
  syntax Language = "language" Name:Identifier "{" Members:Member* "}";
  syntax Member = Extensions / Grammar / Start / Catalog / Nitrogen;
  syntax Extensions = "extensions" Items:(Extension; ",")+ ";";
  syntax Grammar = "grammar" Paths:(Path; ",")+ ";";
  syntax Start = "start" Rule:QualifiedName ";";
  syntax Catalog = "catalog" Paths:(Path; ",")+ ";";
  // Only what differs for Nitrogen; a `grammar` here replaces the outer list.
  syntax Nitrogen = "nitrogen" "{" Members:NitrogenMember* "}";
  syntax NitrogenMember = Namespace / Grammar / Source;
  syntax Namespace = "namespace" Name:QualifiedName ";";
  syntax Source = "source" Paths:(Path; ",")+ ";";
}
```

`languages/project/project.json`: `{"mode":"syntax","start":"NitrideProject.File","grammars":["Project.ngr"]}`.

### Task 2: Resolving `.nproj` files (`nproj.rs`)

**Files:**

- Modify: `crates/nitride-prepare/src/lib.rs` (re-exports)

**Interfaces:**
- Consumes: `project_language()` (Task 1).
- Produces:

```rust
pub struct ProjectLanguage {
    pub path: PathBuf,                // the .nproj
    pub name: String,
    pub extensions: Vec<String>,      // with leading dot, source order
    pub grammars: Vec<PathBuf>,       // joined to the .nproj's dir, source order
    pub start: String,
    pub start_span: [usize; 2],
    pub catalogs: Vec<PathBuf>,
    pub nitrogen: Option<NitrogenSection>,
}
impl ProjectLanguage { pub fn typed(&self) -> bool /* !catalogs.is_empty() */ }
pub struct NitrogenSection {
    pub namespace: String,
    pub grammars: Vec<PathBuf>,       // the replacement list, or the outer list when none is given
    pub sources: Vec<PathBuf>,
}
pub struct ProjectWorkspace {
    pub languages: Vec<ProjectLanguage>,
    pub errors: Vec<PrepareError>,    // each with the path and span of the offending .nproj
}
/// One language file. `exists` reports whether a referenced file exists (editor buffers count).
pub fn read_language(source: &Source, exists: &dyn Fn(&Path) -> bool) -> Result<ProjectLanguage, Vec<PrepareError>>;
/// A workspace file and every language it includes, in include order.
pub fn read_workspace(source: &Source, read: &dyn Fn(&Path) -> Option<String>, exists: &dyn Fn(&Path) -> bool) -> ProjectWorkspace;
pub fn project_outline(source: &Source) -> Result<Vec<GrammarItem>, PrepareError>;      // kinds "language"/"workspace"
pub fn project_references(source: &Source) -> Result<Vec<ProjectReference>, PrepareError>;
pub struct ProjectReference { pub kind: &'static str /* "file" | "rule" */, pub text: String, pub span: [usize; 2], pub target: Option<PathBuf> }
```

Decode the tree the way `catalog.rs`'s `Decoder` does. Syntax errors come back as a single error carrying the parse span. `read_workspace` lists each include folder (`std::fs::read_dir`) for `*.nproj`.
