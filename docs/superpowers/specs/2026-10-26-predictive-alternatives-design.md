# Recognition-only trials for measured failed syntax alternatives

## Goal and evidence
Roslyn remains the target. Refreshed paired Stage24/Roslyn cold medians at16MiB are7.648903375s/1.284679s (~5.95x gap); Roslyn separate warm median0.6375265s. Same CSharp4 inputs, no diagnostic instrumentation in timing builds. A temporary separate profiler measured4MiB:2,458,835 node-record constructions and679,720 releases. ## Small first production target
Add generic compiler selection for nonlexical, ownerless rules whose body is exactly a two-part sequence: first a possibly labeled Ref to a nonlexical rule, second a possibly labeled Ref to a lexical rule with a mandatory leading single ASCII punctuation literal (possibly followed by predicates/other suffix). Resolve that lexical leading literal only through bounded labels/sequences with a directly mandatory first literal; do not infer through choices/nullable prefixes/cycles. This selects NullableType in the admitted CSharp4 grammar without hard-coded names or IDs. Emit a byte marker table in CompiledParser using an additive new_with_trials constructor; old new remains valid with no trials. Bad table length declines the specialization.

The marker is a bounded strategy heuristic, never a parsing proof. If the marker occurs in the next64 raw bytes, run the ordinary tree builder. If absent, run the unchanged grammar in recognition-only syntax mode. A failure returns that actual grammar failure and its actual observations/furthest/work. A success discards virtual state and runs the ordinary tree builder. Heuristic mistakes (long types, comments, Unicode) therefore affect cost only, not which grammar alternatives match. The raw heuristic read needs no dependency observation because it does not determine recognition; the actual recognizer runs in either path.

## Activation and limits
Only generated cold parsing, default Limits exactly, alias_nodes=false/token_children=false. Default strict_comments either value is supported. Custom work/frame/stack/depth settings, default APIs, edited ropes and recovery probes retain original behavior. No work rollback: count every grammar expression actually executed, including a successful trial followed by real construction. Source position/arena trail/checkpoint-next are restored before successful replay. Errors restore mode/trail and propagate to the existing cold-native fallback. Original function stack guards and all grammar choices/ranking still execute; no syntax alternative is selected by lookahead. A per-Parser trial eligibility flag avoids repeated Limits comparisons.

## Recognition-only syntax representation
Add a second private reserved SubtreeId within the already invalid/exhausted u32::MAX chunk, distinct from NONE even for zero-width matches. It is a virtual successful syntax handle and can never be published. Reserved-chunk lookup must decline it. During a trial and only when in_token==0, add_node returns a virtual handle preserving start/width instead of allocating syntax. In any lexical context keep normal existing allocation/caching semantics: lexical tree payload must never contain virtual children. Nested lexical no-node behavior remains as before.

Use a dedicated Children recognition sink that counts edges and retains first handle for alias reduction, while ignoring payload/label storage. Existing sink behavior remains unchanged. All real lexical/memo temporary owners still roll back normally. stand_in treats virtual syntax as already reduced; tree shape is irrelevant for recognition. Pratt selection still uses source position/precedence. Cache real normal hits/failures as before, but never store a successful virtual Pratt handle and never publish rule facts during a trial. This preserves the real recognizer's furthest/depth/observations, rather than manufacturing failure metadata from a scan. Actual syntax is built normally after a successful trial.

## Isolation, counters and acceptance
No per-source dynamic cache or private budget enlargement. Add operation counters for trial attempts, failures and successful replays. Virtual handles must not escape into memo hits, recognition facts, published nodes or materialization. Test empty/transparent aliases, nested Pratt, lexical→syntax references, failures/successful replays/errors, tight budgets disabled, Unicode/comments and edit-to-error behavior. Full canonical shape/diagnostic comparisons against the independent interpreted parser remain required.

Keep only repeatable uninstrumented paired gains at256KiB/4MiB/16MiB. Diagnostic builds are archived and excluded from timing. Full suite/clippy/fmt/bootstrap/Python, all4334/1286 differential traces, validated recovered16MiB first edit and two100000-edit reader windows, exact source/executable fingerprints, independent review. If trials lose or cannot satisfy virtual-handle safety, archive/revert and report the measured result. All work remains local/uncommitted; no grammar change, conformance expansion, default-backend cutover or Roslyn parity claim.
