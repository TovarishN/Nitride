# Fused generated ASCII lexical decisions

## Intent and approved scope
Reduce full-parse execution cost on the current Stage22 parser, toward Nitrogen initial-incremental throughput, using the user-approved generated lexical decision milestone. Baseline current16MiB full parse is8.058s versus Nitrogen5.069s with reuse data. Lexical scanners account for506,889,738 of1,030,258,386 logical steps; logical counts are not CPU percentages. Refresh CPU sampling before implementation and keep only repeatable measured gains.

## Design
For each admitted generated lexical rule, evaluate its normalized expression at compile time for each possible ASCII first byte. A decision is available only when the result is fully determined by that first byte, consumes zero or one byte, and executes no runtime rule reference. Ordered choices, nested class/literal tests, labels, predicates, empty sequences and failed/optional repeats may qualify. A sequence after consuming a byte is unknown unless it ends there. A matching multi-byte literal or repeat requiring a following byte is unknown. Encountering an executed Ref is unknown; untaken branches need not be inspected. This restriction preserves all existing generated function-entry stack guards.

Each available decision records exact logical work, maximum depth relative to the root expression, maximum observed byte reach, match result and zero/one consumption. Every generic expression charges one step; descendants increase depth exactly as existing emit does. Predicates/failed ordered alternatives preserve observations/work while restoring position. Failed literals observe their full byte width even if the first byte differs; class/any observe one ASCII byte. Root generated c.enter(d) and exclusions remain outside the fused expression and run unchanged.

Emit an immutable128-entry table only when some available trace costs at least four logical steps. Pack each entry in a private u64 through public opaque AsciiDecision::new(work:u16, depth:u8, observed:u32, matched:bool, advance:bool); zero work denotes unavailable. Static evaluator limits: at most4096 visited expression nodes per ASCII entry and depth64; overflow or unsupported input yields unavailable, never approximate metadata. Add no per-parse cache or allocation.

LexicalContext::ascii_decision(&[AsciiDecision;128], depth:u32)->Option<bool> returns None without changing any state when EOF/non-ASCII/unavailable, metadata is unsafe, or full-trace work/frame headroom is insufficient. Otherwise it adds the exact recorded work, folds maximum depth and clamped read reach, optionally advances one ASCII byte, and returns the recorded match. Fallthrough executes the unchanged generated expression, including partial work and failure position at limits. The generated root function always calls its original enter guard before either path. Runtime references, Unicode, unknown suffix cases and EOF retain their existing bodies. No callbacks are retained by edited snapshots; probes/default APIs remain interpreted as before.

## Constraints and acceptance
No grammar, API default, precedence, label, exclusion, recovery policy, private budget or ownership changes. Public decision metadata is opaque; malformed advance-without-match or insufficient observed reach must decline safely. Preserve all existing syntax and diagnostics, UTF8 boundaries, read dependencies and low-work/depth behavior. Preserve physical stack checks by never fusing an executed runtime reference and keeping enter guard at the original root boundary. Static table/source/executable size must be reported.

First run focused metadata/evaluator/reference tests and generated whole-parser differential checks. Compare uninstrumented frozen Stage22/candidate at256KiB/4MiB/16MiB in alternating three-round batches; repeat promising results. If retained, full workspace/clippy/fmt/bootstrap/Python, standard4334/adversarial1286, recovered16MiB validated edit and both100000-edit reader windows, exact source/executable identity, and one independent final review. If no convincing gain, archive owned prototype files and restore exact Stage22 with fresh local gates. Keep all work local and uncommitted; preserve earlier checkpoints. No Roslyn parity or universal performance claim.
