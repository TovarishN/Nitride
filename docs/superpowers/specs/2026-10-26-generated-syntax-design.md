# Generated syntax execution

The user approved generating ordinary syntax execution toward Roslyn full-parse speed, retaining the existing tree builder and compatibility interpreter. Build on verified Stage18. Generate Rust callbacks from admitted grammar IR for sequences, repeats, labels, references and literals. Choices, predicates, classes, wildcard and nested Pratt shapes use the existing expression interpreter. Extensible Pratt roots, ranking, ambiguity, associativity, prefix/infix selection, node allocation/ownership and recognition-index publication remain in the current parser.

Builder decisions: generated callback tables hold ordinary rule bodies and infix tails, paired with the existing generated lexical table in a new CompiledParser/PARSER artifact. Owner-bearing rule sequences retain the current root-sequence tick omission and pass the supplied minimum only through labels to a direct final owner reference. Infix tail callbacks run after the existing left operand is validated and inserted; tail matching never chooses the winner. Eligible expression traversal is capped at depth64,4096 nodes per rule and1,000,000 globally; unsupported or oversized bodies remain interpreted. No syntax-reference expansion at build time, so recursive rule graphs stay on the existing guarded runtime rule calls.

Expose parse_snapshot_generated(&PARSER,source,limits,mode); preserve Stage18 parse_snapshot_compiled/LEXERS behavior and default APIs. Generated bodies borrow the current Parser and Children through a concrete public hidden SyntaxContext. Keep all primitive trivia/keyword boundaries, labels, failure furthest, source observations, repeat marks and checkpoint restoration, logical work/depth checks and actual rule/interpretation stack guards. Generated inline structural nodes need logical checks; entry/reference/interpreter paths retain physical stack checks. Native scanner and syntax state is not retained by published snapshots. Edited ropes and recovery probes stay interpreted. Any generated cold parse error retries the established entry point to preserve diagnostics/recovery budgets.

Validation: RED→GREEN generation, precedence/alias/tree-mode/repeat/dependency/limit regressions; one final read-only review with one TDD fix pass; full suite/clippy/fmt/bootstrap/driver checks; measurable benefit against frozen Stage18 on identical inputs; complete standard/adversarial traces, validated recovered first edit, reader-window checks and accurate source/executable hashes. Distinguish logical work from CPU-time attribution; do not claim Roslyn parity without measurements. Preserve prior dirty work, all checkpoint artifacts, no commits or integration.

CPU-guided primitive optimization: in generated mode only, trivia exits after a non-slash, non-whitespace character without testing comment prefixes. It retains the original two-byte observation reach and logical tick count. ASCII/Unicode/EOF/comment/error comparisons pin equivalence. This addition is measured separately from structural generation.
